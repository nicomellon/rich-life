# Frontend

The Rich Life web app: React 19 and TypeScript on Vite, with React Router for routing and TanStack Query for server state. The UI uses [shadcn/ui](https://ui.shadcn.com/) components on Tailwind CSS v4.

## Running

From the repository root, `make setup` installs the dependencies and `make frontend` starts the dev server (`make dev` runs it alongside the API). To do it by hand:

```sh
cd frontend
npm ci
node --env-file=../.env node_modules/vite/bin/vite.js   # http://localhost:5173
```

Plain `npm run dev` works too; without `API_PROXY_TARGET` in the environment it uses the default below.

## Configuration

The built app has **no configuration of its own**: it calls the API on the origin it's served from, under `/api/v1`. The server in front of it decides where `/api` goes. In development that's the Vite dev server (and `npm run preview`), which proxies `/api` to the backend. In production it will be the web server that serves `dist/` (#20). One build can therefore run in any environment, and the browser never makes a cross-origin request, so CORS doesn't come into play.

Following the [twelve-factor](https://12factor.net/config) approach, the dev server reads its settings **only from environment variables**. Vite's own `.env` file loading is turned off (`envDir: false` in `vite.config.ts`). For local development, `make frontend` loads the root `.env` into the environment with `node --env-file`; direnv or exporting the variables in your shell works just as well.

| Variable | Default | |
|---|---|---|
| `API_PROXY_TARGET` | `http://localhost:8000` | Backend that the dev and preview servers forward `/api` requests to |

## Layout

| Path | Contents |
|---|---|
| `src/main.tsx` | Entry point: query client, router and global styles |
| `src/routes.tsx` | Route tree, shared by the browser router and the tests |
| `src/components/layout/` | App shell (header, navigation, page container) |
| `src/components/ui/` | shadcn/ui components, generated by the CLI |
| `src/pages/` | One component per route |
| `src/lib/api.ts` | API client: a `fetch` wrapper that adds the `/api/v1` prefix and the access token, parses JSON and throws `ApiError` on non-2xx responses |
| `src/lib/auth-token.ts` | Access token storage (localStorage) |
| `src/lib/query-client.ts` | TanStack Query defaults (no retries on 4xx) |
| `src/test/setup.ts` | Vitest setup: jest-dom matchers and per-test cleanup |

Import from `src` with the `@/` alias, e.g. `import { api } from '@/lib/api'`.

### Calling the API

```ts
import { api } from '@/lib/api'

const buckets = await api.get<Bucket[]>('/buckets')
await api.put('/buckets', updatedBuckets)
```

Errors are `ApiError` instances with the HTTP `status` and FastAPI's `detail`.

### Adding UI components

```sh
npx shadcn@latest add dialog
```

Components are copied into `src/components/ui/` and are ours to edit. Theme tokens live in `src/index.css`.

## Checks

```sh
npm test               # Vitest + React Testing Library
npm run lint           # ESLint
npm run format:check   # Prettier (npm run format to fix)
npm run typecheck      # tsc
npm run build          # type check and production build into dist/
```

`make test` and `make lint` from the repository root run these along with the backend's checks.
